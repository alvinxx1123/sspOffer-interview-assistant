# 概念提取规则

把简历经历的"做了什么"映射成面试官会深挖的"底层概念树"。原则：落在该经历涉及的技术栈上，不要泛泛罗列八股。

## 提取维度

对每条经历，从以下角度挖概念：

- 原理层：用到的技术为什么有效、核心机制是什么（如 Redis 单线程+IO多路复用、索引 B+树为什么）
- 故障层：线上会怎么坏、怎么防（缓存击穿/穿透/雪崩、限流降级、重试幂等）
- 一致性层：多写/并发/分布式下的正确性（缓存一致性、分布式锁、消息可靠投递）
- 选型层：为什么是它不是别的（Redis vs Memcached、Kafka vs RocketMQ、同步 vs 异步）
- 边界层：容量、极限、成本、监控（QPS 上限、数据量膨胀、熔断阈值）

## 概念字段

- name：概念名（中文，简短，如"缓存击穿"）
- category：所属维度（原理/故障/一致性/选型/边界）
- depthLevel：表层 / 中层 / 底层（后续施压可按难度递进）
- whyItMatters：面试官会怎么拷打这一点的核心动机
- probeQuestion：一道开放式诊断题，逼对方解释（为什么/怎么处理/权衡了什么），禁止是非题

## 数量与质量

- 每条经历 2-5 个概念，宁少而准，不要凑数。
- 概念要和该经历写到的技术栈强相关；经历没提到的技术不要硬塞概念。
- probeQuestion 要让对方"讲出来"，例如"请解释缓存击穿是什么、你当时怎么处理、为什么选这个方案"，而不是"你了解缓存击穿吗"。
